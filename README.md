# Runway Models — техническое задание проекта

**Репозиторий:** `true-adam`

**Команда:** Алишер, Манас, Куаныш, Хамзат

**Формат:** учебный командный веб-проект на Next.js

## 1. Идея и цель

Runway Models — сайт о подиумных моделях, показах, съёмках, кастингах и обучении. Посетители смогут узнать даты мероприятий, посмотреть портфолио моделей, подать заявку на кастинг и записаться на курс. Бренды и фотографы смогут оставить запрос на подбор модели для своего проекта.

Главные сценарии:

- **Событие → подробности → заявка на участие.**
- **Модель → портфолио → приглашение на съёмку.**
- **Курс → программа и расписание → запись на обучение.**

## 3. Участники проекта и роли пользователей

Проект объединяет тех, кто участвует в показах и съёмках, организует мероприятия, обучает моделей или следит за модой как зритель. Ниже описаны **планируемые роли и возможности готовой платформы**. Сейчас регистрация, кабинеты и разграничение доступа ещё не реализованы.

### 3.1. Пользователи сайта и их возможности

| Роль | Кто это и зачем приходит | Что сможет делать на сайте |
| --- | --- | --- |
| **Гость** | Посетитель без регистрации | Смотреть опубликованные показы, съёмки, модели, курсы и backstage; искать и фильтровать информацию; читать условия участия; перейти к регистрации |

| **Преподаватель / тренер** | Специалист по дефиле, позированию или работе перед камерой | Вести назначенные ему курсы, редактировать программу и расписание, публиковать учебные материалы, просматривать заявки и список учеников своих групп, отмечать посещаемость |
| **Модератор / контент-менеджер** | Сотрудник платформы, проверяющий контент | Проверять предложенные профили, мероприятия и материалы; публиковать их или возвращать на исправление с причиной; обрабатывать жалобы, обновлять информационные разделы; не назначать административные роли |

**«Пользователь» — общее название зарегистрированного человека, а не отдельная профессия.** После регистрации ему доступны базовый кабинет и возможности зрителя. Один человек может совмещать роли, например модель и ученик или фотограф и организатор. Представитель организации использует личную учётную запись, связанную с этой организацией.

### 3.2. Права доступа и границы ролей

- Без входа доступна только опубликованная общедоступная информация. Для подачи и отслеживания заявок, записи и работы с личными данными нужен вход.
- Пользователь управляет своим профилем, избранным, заявками и записями. Он не может менять чужие данные или самостоятельно назначать себе роль администратора, модератора, преподавателя или организатора.
- Профессиональная роль и её область ответственности подтверждаются администратором. Разрешение управлять моделью для агентства выдаётся с её согласия и может быть отозвано.
- Организатор получает доступ к заявкам только на свои мероприятия; преподаватель — к ученикам и материалам только назначенных ему курсов; приглашённый специалист — к информации о своих проектах.
- Контакты и фотографии из анкеты кастинга не появляются автоматически в публичном профиле. Их видят заявитель и ответственные за обработку этой заявки сотрудники. Модератор проверяет назначенный ему контент; административные действия фиксируются.
- Запись зрителя на открытый показ отличается от заявки модели на участие в показе. Закрытые кастинги и внутренние съёмки не принимают зрительские записи.
- При переносе или отмене события организатор обновляет его статус; участники видят новое состояние в своих записях. Публичный статус мероприятия не заменяет личный статус заявки.
- Проверка прав выполняется на сервере: скрытой кнопки в интерфейсе недостаточно. Публикация, изменение чужого объекта и назначение ролей должны проверять роль и принадлежность данных.

Референсы Balmain Paris 2016, Chico Lachowski, Jordan Barrett и Sean O’Pry обозначают визуальное направление и не считаются подтверждёнными участниками проекта.

### 3.4. Как участники взаимодействуют

1. **Показ или съёмка:** организатор готовит мероприятие → модератор проверяет публикацию → модель подаёт заявку → организатор рассматривает её и формирует команду → выбранные участники получают подтверждение и расписание.
2. **Посещение показа:** зритель выбирает открытое событие → отправляет запись → получает статус подтверждения или ожидания → при необходимости отменяет свою запись. Для закрытых событий этот сценарий недоступен.
3. **Подбор модели:** бренд или фотограф отправляет запрос → ответственный организатор уточняет условия → предлагает подходящие модели → модель принимает или отклоняет приглашение.
4. **Обучение:** преподаватель готовит программу курса → курс публикуется → ученик записывается → ответственный подтверждает запись → ученик видит расписание и материалы.
5. **Backstage:** команда передаёт материалы → модератор проверяет содержание и подписи авторов → материалы появляются в публичной галерее.

Минимальные статусы заявки: **отправлена, на рассмотрении, принята, отклонена, отозвана**. Для записи зрителя или ученика используются **ожидает подтверждения, подтверждена, отменена**, а при ограничении мест — **лист ожидания**. Изменение статуса доступно владельцу записи для отзыва/отмены и ответственному за мероприятие или курс для решения по заявке.

## 4. Дизайн

Бело-чёрный стиль с серыми оттенками для второстепенной информации. Крупные заголовки, выразительные фотографии, много свободного пространства и сетка в стиле модного журнала. Плавные переходы, заметный фокус клавиатуры и удобная мобильная версия.

**Референсы главного экрана:** Balmain Paris 2016, Chico Lachowski, Jordan Barrett и Sean O’Pry. Команда подберёт фотографии и оформит их в коллаж или галерею «Вдохновение». Референсы отделяются от каталога участников проекта.

Главные действия: «Стать моделью», «Ближайшие показы», «Подобрать модель».

## 5. Функциональные требования

### Главная страница

Логотип, меню, первый экран с фотографиями-референсами, описание проекта, ближайшие события, избранные модели, направления обучения, блок backstage и контакты. Кнопки ведут к соответствующим разделам.

### Показы и календарь

- Карточки с датой, временем, городом, местом и фотографией показа.
- Просмотр списком и календарём; поиск, фильтры по городу, типу и дате, сортировка по дате.
- Страница события с описанием, условиями участия, требованиями и сроком подачи заявки.
- Переход к анкете с выбранным событием. Прошедшие события отмечаются отдельно и не принимают новые заявки.
- Для открытых показов — отдельная запись зрителя с количеством доступных мест и статусом подтверждения. Состав зрителей и состав моделей ведутся раздельно.

### Съёмки

- Список проектов: fashion, editorial, коммерческие съёмки и тесты для портфолио.
- Название, дата, место, организатор, требования к моделям и условия участия.
- Заявка на конкретную съёмку.

### Каталог моделей и портфолио

- Карточки с фотографией, именем, городом, ростом и специализацией.
- Поиск по имени и фильтры по городу и специализации.
- Профиль: галерея, параметры, опыт и видео дефиле при наличии.
- Кнопка «Пригласить на съёмку» открывает запрос с выбранной моделью.
- Понятное сообщение, если поиск не дал результатов.

### Кастинги и набор моделей

- Открытые кастинги, требования и сроки.
- Анкета: имя, город, контакт для связи, рост, параметры, опыт и фотографии.
- Связь анкеты с выбранным кастингом, показом или съёмкой.
- Проверка обязательных полей, формата контактов, типа и размера фотографий.
- Согласие на обработку данных перед реальной отправкой; состояния загрузки, успеха и ошибки; защита от повторной отправки.

### Обучение

- Направления: дефиле, позирование и работа перед камерой.
- Карточки курсов: программа, преподаватель, длительность, стоимость, формат и ближайшая дата.
- Расписание занятий и запись на выбранный курс.

### Backstage и сотрудничество

- Галерея фотографий и коротких видео с подготовки к показам и съёмкам; подписи и связь с событием.
- Раздел для брендов и фотографов с формой «Подобрать модель».
- В запросе: имя/бренд, контакт, описание проекта, дата, город и выбранная модель при наличии.

### Учётные записи и управление

- Регистрация, вход и базовый кабинет с собственным профилем, избранным, заявками, приглашениями и записями.
- Состав действий кабинета зависит от подтверждённых ролей из раздела 3: мероприятия организатора, курсы преподавателя, портфолио модели и другие назначенные объекты.
- Интерфейс модерации публикаций и административное управление пользователями и ролями.
- Назначение ответственных за мероприятие или курс и фиксация решений по заявкам.
- Эти функции относятся к будущему этапу серверной части; при демонстрации без авторизации они должны быть отмечены как прототип.

## 7. Технологии и данные

Установлено: **Next.js 16.4.2, React 19.3.0, TypeScript, Tailwind CSS 4, ESLint**. Используются App Router и импорт из `src/` через `@/*`.

Проверка зависимостей при подготовке: `npm audit --omit=dev` — 0 уязвимостей. Полный `npm audit` сообщает о 5 предупреждениях высокой важности в цепочке dev-зависимостей ESLint (`braces` → `micromatch` → `fast-glob`). Автоматическое исправление предлагает откат конфигурации Next.js до другой основной версии, поэтому оно не применялось. Команда должна отслеживать совместимое исправление этих инструментов.

Сначала интерфейс разрабатывается на типизированных демонстрационных данных в `src/data/`. Пробные формы и демонстрационные записи должны быть явно обозначены.

Затем команда добавит серверные обработчики Next.js, серверную проверку полей, базу данных для заявок и отдельное хранилище фотографий. Конкретные сервисы будут выбраны перед реализацией. Сообщение об успешной отправке показывается только после подтверждения сервера.

Основные сущности: `User`, `Role`, `Organization`, `Model`, `Event`, `Shoot`, `Casting`, `Course`, `Application`, `Registration`, `Invitation`, `Favorite`, `MediaItem`. Учётная запись может иметь несколько подтверждённых ролей. Для объектов сохраняются владелец и назначенные ответственные; для связи агентства и модели — согласованное право представления.

`Application` описывает заявку на участие или сотрудничество, `Registration` — запись зрителя или ученика, `Invitation` — приглашение в проект. У каждой записи есть автор, тип, статус и связь с конкретным событием, моделью, съёмкой или курсом. Это позволяет отличать отбор модели от посещения показа зрителем.

Авторизация, базовые кабинеты и управление ролями запланированы вместе с серверной частью. Онлайн-оплата, внешние уведомления и отдельные кабинеты партнёров — возможное развитие после основной версии.

## 8. Что будет делать команда

| Участник | Ответственность | Результат |
| --- | --- | --- |
| **Алишер** | Основа Next.js, общая структура и главная страница | Шапка, меню, подвал, главная, общие стили, адаптивность и интеграция частей проекта |
| **Манас** | Каталог моделей, портфолио, backstage и сотрудничество | Карточки, поиск и фильтры, профиль модели, галереи и запрос от бренда/фотографа |
| **Куаныш** | Показы, календарь и съёмки | Даты, карточки и подробности событий, фильтры и сортировка, список съёмок и переход к заявке |
| **Хамзат** | Кастинги, набор моделей и обучение | Анкета, проверка полей и фотографий, карточки курсов, расписание и запись на обучение |

Общая работа: согласование типов данных и компонентов, подключение отправки заявок, авторизации и проверки прав, проверка мобильной версии, доступности и сценариев всех ролей. Каждый участник реализует действия пользователей в своих разделах. Алишер координирует общую структуру кабинета и интеграцию ролей; Манас — профили и сотрудничество; Куаныш — работу организатора и записи зрителей; Хамзат — заявки моделей, кабинеты ученика и преподавателя. Каждый участник пишет код и делает коммиты своей части. Общие файлы `layout.tsx`, `globals.css` и зависимости меняются по согласованию команды.

## 9. Этапы разработки

1. Подготовить репозиторий, Next.js и ТЗ — текущий этап.
2. Согласовать макет, фотографии, типы данных и общие компоненты.
3. Разработать страницы на демонстрационных данных по распределению задач.
4. Добавить фильтры, сортировку, календарь и переходы между страницами.
5. Подключить авторизацию, кабинеты и права ролей, серверную обработку заявок и записей, хранение данных и загрузку фотографий.
6. Проверить проект на разных экранах, исправить ошибки и подготовить демонстрацию.

## 11. Запуск

Нужен **Node.js 24 LTS** с npm. После скачивания репозитория откройте терминал в папке `true-adam`:

```bash
npm ci
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Если порт занят, используйте адрес из терминала. Для остановки — `Ctrl+C`.

На Windows можно запустить **`START-DEV.cmd`**: он найдёт Node.js, при необходимости установит зависимости и запустит сервер. После установки Node.js перезапустите VS Code, чтобы обычный терминал увидел `npm` и `npx`.

Проверка и production-запуск:

```bash
npm run lint
npm run build
npm start
```

`npm start` выполняется после успешного `npm run build`. Двойной щелчок по HTML и расширение Live Server для Next.js не используются.

Основа создана командой ниже; повторно запускать её в готовом проекте не нужно:

```bash
npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-npm --empty --no-react-compiler --no-cache-components --no-agent-feedback --disable-git --yes
```

## 12. Структура и Git

```text
true-adam/
├── src/app/
│   ├── globals.css       # Общие стили
│   ├── layout.tsx        # Корневой layout и метаданные
│   └── page.tsx          # Стартовая главная страница
├── next.config.ts       # Настройки Next.js
├── eslint.config.mjs    # Настройки проверки кода
├── tsconfig.json        # Настройки TypeScript
├── package.json         # Зависимости и команды
├── package-lock.json    # Зафиксированные версии зависимостей
├── START-DEV.cmd        # Запуск на Windows
└── README.md            # ТЗ и инструкции команды
```

В процессе разработки появятся `src/components/`, `src/data/`, `src/types/`, `public/images/` и остальные маршруты из плана.

Перед работой каждый участник обновляет общую версию, создаёт ветку под свою задачу и делает небольшие понятные коммиты. В основную ветку изменения попадают после проверки командой. `package-lock.json` хранится в Git; `node_modules`, `.next` и локальные `.env` исключены через `.gitignore`.
